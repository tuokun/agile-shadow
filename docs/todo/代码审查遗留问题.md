# 代码审查遗留问题

2026-05-19 全面审查后，已修复的关键 Bug 和代码质量问题不再列出，以下为明确不修或后续迭代的设计/优化问题。

## 性能优化

### HandwritingBoard O(n²) 拖拽路径拷贝

`currentPath = currentPath + change.position` 每次拖拽事件创建新不可变列表，整笔划逐点累计为 O(n²)。应改用 `mutableStateListOf` 或 `SnapshotStateList`，在 `onDrag` 中 `add`，避免每次全量拷贝。

**涉及文件**: `ui/keyboard/HandwritingBoard.kt`

### 主线程阻塞 I/O（RimeEngine 启动）

`RimeEngine.startup()` 在 `YeyingImeService.onCreate()` 中同步调用，包含递归 asset 目录遍历和文件拷贝。应改为后台协程执行，避免输入法服务初始化 ANR。

**涉及文件**: `YeyingImeService.kt`, `engine/RimeEngine.kt`

### N+1 asset 目录检测

`copyAssetDir` 递归时为每个条目额外调用 `assetManager.list(src)` 判断是否为目录，每层级翻倍 I/O 调用。考虑按文件扩展名约定区分，或改用 `open()` 捕获异常的方式。

**涉及文件**: `engine/RimeEngine.kt:copyAssetDir`

### LiquidGlass 逐帧开销

`dp.toPx()` 和 `Color.White.copy(alpha = ...)` 及 `Brush.verticalGradient()` 等在 `drawBehind` lambda 内每帧重新计算/分配。应将密度无关常量提升至 composition 层缓存，`Color` 和 `Brush` 预计算为顶层常量。

**涉及文件**: `ui/theme/LiquidGlass.kt`

### T9 键码查询每字符调用 `lowercaseChar()`

`pinyinToT9` 热路径上每字符调用 `lowercaseChar()`，内部可能涉及临时字符串分配。由于仅需 ASCII 小写映射，可改用 `charToT9[it.lowercaseChar()]` 替代为 code 索引或 `when` 分支。

**涉及文件**: `engine/T9Mapper.kt:pinyinToT9`

## 架构重构

### QWERTY / T9 键盘结构重复

两个键盘 composable 共享相同的 `Column → Row → key button` 迭代脚手架，仅按钮样式和点击逻辑不同。应提取 `KeyboardSurface` 通用 composable，接受 `rows` 数据和 `keyFactory` lambda。

**涉及文件**: `ui/keyboard/QwertyKeyboard.kt`, `ui/keyboard/T9Keyboard.kt`

### T9 键盘 UI 层处理特殊键码

`T9Keyboard` 的 `when (key.code)` 分支在 UI 层解释 `KEYCODE_CLEAR → ClearComposition` 等业务映射。应下沉到 ViewModel，UI 层只传递键码，ViewModel 负责路由。

**涉及文件**: `ui/keyboard/T9Keyboard.kt`

### DataStore setter/getter 模板重复

`Prefs.kt` 中 4 个 setter 方法结构完全一致，4 个 getter Flow 结构完全一致。可提取通用 `setPref(key, value)` 和 `getPref(key, default)` 辅助方法。

**涉及文件**: `data/Prefs.kt`

### KeyboardViewModel 直接依赖 RimeEngine 单例

`KeyboardViewModel` 硬编码引用 `RimeEngine.instance`，无法单元测试。后续应注入接口或使用依赖注入框架。

**涉及文件**: `ui/keyboard/KeyboardViewModel.kt`

### Structs 中 Array 字段强制手写 equals/hashCode

`RimeMenu` 和 `RimeContext` 包含 `Array` 字段，data class 自动生成的 equals/hashCode 使用引用比较，必须手写覆盖。如果 JNI 接口允许，改为 `List` 可消除此样板代码。

**涉及文件**: `com/yuyan/inputmethod/core/Structs.kt`

### ClipboardPanel 直接暴露 DAO 给 UI

`ClipboardPanel` composable 直接接收 `ClipboardDao` 参数，UI 层直接耦合 Room 持久层。应通过 ViewModel 或 Repository 中介。

**涉及文件**: `data/clipboard/ClipboardPanel.kt`

## 功能缺口

### 提交文本到编辑器（commitText）未实现

`KeyboardViewModel` 中 `handleKeyPress` 和 `handleCandidateSelect` 已正确获取 commit text，但未调用 `InputConnection.commitText()` 将文本实际发送到目标编辑器。需要从 `YeyingImeService` 传递 `InputConnection` 到 ViewModel 层。

**涉及文件**: `ui/keyboard/KeyboardViewModel.kt`, `YeyingImeService.kt`

### SymbolPanel 多码点符号提交不完整

当前用 `symbol.codePointAt(0)` 获取符号首码点作为 keycode 发送。对于多码点序列（如带变体选择器的 emoji）只能发送首个码点。后续应改为 `commitText` 直接提交完整字符串。

**涉及文件**: `ui/symbol/SymbolPanel.kt`

### T9 键盘 Shift 切换未实现

`T9Keyboard` 中 `KEYCODE_SHIFT` 分支为 no-op，标注 TODO。需要实现大小写/英文模式切换。

**涉及文件**: `ui/keyboard/T9Keyboard.kt`

### CapsState 枚举定义但未使用

`KeyboardState` 中移除了 `capsState` 字段，但 `CapsState` 枚举仍保留在 `KeyboardState.kt` 中。后续实现大写锁定功能时重新接入。

**涉及文件**: `ui/keyboard/KeyboardState.kt`
